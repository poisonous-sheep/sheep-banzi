# 数位背包

**类型：** 思维型

**适用场景：** 体积拆成奇数*2^b，高位到低位下放剩余容量，用奇数部分总和截断状态。

**复杂度与条件：** O((63+n)*LIM)时间、O(n+LIM)空间；LIM=min(W,Σ奇数部分)。

本节围绕题目推导组织，函数版题解不强行封装成struct。旧`模板.cpp`仅作历史对照（若存在），不作为本版推荐复制入口。

## 模型识别与变体

**关键突破：** 按重量最低置位分组，从容量高位向低位处理；可用余额随下一位变成2j+bit。

**状态与建模：** f\[j\]是已处理更高重量组后，在当前计量单位下至少还能容纳j单位的最大价值；过大的余额统一截到lim=所有奇数部分之和，更多余额已无法影响选择。

**优化与限制：** 复杂度O(63×lim+n×lim)，lim依赖奇数部分总和，不仅依赖位数；一般大整数重量不满足小lim就会TLE/MLE。P1048是比较用基础模型，其直接O(TM)更简单。

## 例题 1：P3188 梦幻岛宝珠

[原题](https://www.luogu.com.cn/problem/P3188)

**题意：** 重量很大但w=a*2^b且a<=10的0/1背包。

**观察与规模：** 重量奇数部分≤10，容量大但lim≤10n；输入以n=W=-1结束，每一组必须清空物品。 P1048容量小可直接01背包；P3188容量大但重量能分解为小奇数×2^b，这是额外结构。

**朴素思路：** 容量为W的O(nW)背包在W很大时不可行；把重量简单除2会丢掉奇数和容量的低位。

**关键突破：** 按重量最低置位分组，从容量高位向低位处理；可用余额随下一位变成2j+bit。

**状态与建模：** f\[j\]是已处理更高重量组后，在当前计量单位下至少还能容纳j单位的最大价值；过大的余额统一截到lim=所有奇数部分之和，更多余额已无法影响选择。

**本题映射：** 重量很大但w=a*2^b且a<=10的0/1背包。 Σ奇数部分<=10n，使容量与2^30脱钩。 每组建立对象add全部物品，qur(W)，读到-1 -1终止。

**转移与正确性：** 先将高位余额j映射到min(lim,2j+bit)，再处理本组物品：若原来可容纳j+w，则选它后余额j、价值加v。j正序，因此来源j+w还未被本件更新，实现01选择。

**初始化与顺序：** f\[0\]=0，其余-INF；从b=62到0，每层g清空。重量必须正，ctz(0)未定义。每组每件的余额循环正序，不能照搬消耗容量写法的倒序。

**优化与限制：** 复杂度O(63×lim+n×lim)，lim依赖奇数部分总和，不仅依赖位数；一般大整数重量不满足小lim就会TLE/MLE。P1048是比较用基础模型，其直接O(TM)更简单。

**本题复杂度：** O((63+n)*10n)时间、O(n)量级状态空间。

[完整函数题解](%E4%BE%8B%E9%A2%98/P3188-%E6%A2%A6%E5%B9%BB%E5%B2%9B%E5%AE%9D%E7%8F%A0-%E9%A2%98%E8%A7%A3.cpp)。

**启发式总结：** 容量大时先观察重量结构，寻找尺度变化后仍很小的状态。截断状态必须证明未来最大需求上界，不可仅因为空间不足就截断。

## 例题 2：P1048 采药

[原题](https://www.luogu.com.cn/problem/P1048)

**题意：** 每株草药只能采一次，限定时间内最大收益。

**观察与规模：** T≤1000、M≤100；每种药材只能采一次，时间和价值给出，正是有限容量01选择。

**朴素思路：** 枚举全部子集2^M不可行；只选单位时间价值最高的药材不一定能填好剩余时间。

**关键突破：** 按药材逐个决策，只需记录已使用时间或允许时间，不需记住具体已选集合。

**状态与建模：** 处理前i件后dp\[j\]为总时间不超过j的最大价值；i维由外层循环隐含。

**转移与正确性：** 不选第i件继承dp\[j\]；选它来源为旧dp\[j-w\]+v，二者取max。以最后一件是否选分类，覆盖全部合法子集。

**初始化与顺序：** 空选择价值0，所有dp初0；每件按j从T倒到w，使来源仍是未选当前件的旧层，防止变成完全背包。

**优化与限制：** O(TM)时间、O(T)空间。这份基础题解采用普通背包，P3188再利用小奇数部分和数位缩小大容量状态。

**本题复杂度：** O(TM)时间、O(T)空间。

[完整函数题解](%E4%BE%8B%E9%A2%98/P1048-%E9%87%87%E8%8D%AF-%E9%A2%98%E8%A7%A3.cpp)。

**启发式总结：** 先估算容量DP能否直接通过；仅在容量确实太大并有重量结构时，再考虑数位背包。滚动数组方向取决于是否允许重复取件。

## 共同思路与易错点

- 剩余容量语义的0/1转移必须j从小到大，反向会重复选同一物品。
- 只有奇数部分和小才适合大容量；普通采药例题展示可用但传统背包更直接。
- 不能对0重量调用ctzll；价值和须在long long内。

共同启发：容量大时先观察重量结构，寻找尺度变化后仍很小的状态。截断状态必须证明未来最大需求上界，不可仅因为空间不足就截断。
