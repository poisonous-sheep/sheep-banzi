# 启发式合并

**用途与条件：** 每次枚举小容器合入大容器；保留颜色桶句柄交换与map统计两个原资料模型。

**复杂度：** 位置桶总O(n log n+q)，map树上合并O(n log²n)；空间O(n+颜色数)。

[完整模板](模板.cpp)；模板solve采用第一例题或注明的演示输入。

## 接口

- `build(col,kinds)`：建立颜色位置桶，颜色先离散化为1..kinds
- `change(x,y)`：把逻辑颜色x全部变y，交换物理桶保证小并大
- `info/insert/merge`：map颜色频率统计：合并后mx及sum为众数频率与颜色和

## 例题

### P3201 梦幻布丁

[原题](https://www.luogu.com.cn/problem/P3201)

**题意：** 把一种颜色的全部位置改色，并查询颜色段数。

**为什么使用：** 改色等价合并位置集合，段数只在搬运位置两侧变化。

**如何调用：** 离线读取操作以压缩所有颜色；build、change，查询segments。

**复杂度：** O((n+q)log(n+q)+n log n)时间，O(n+q)空间。

### CF600E Lomsat gelral

[原题](https://codeforces.com/problemset/problem/600/E)

**题意：** 对每棵子树求出现最多的颜色的编号和。

**为什么使用：** 子树统计是孩子容器的并集；小map并入大map并维护频率最大值。

**如何调用：** 每点insert自身颜色，DFS后merge孩子；合并后记录sum。

**复杂度：** O(n log² n)时间、O(n)活动数据与递归空间。

## 易错点

- 交换的是逻辑颜色句柄，不能简单颠倒x->y语义。
- map单次操作还有log因子；复杂度不能仅写O(n log n)。
- 数组边界使用显式判断，不依赖颜色0哨兵。
