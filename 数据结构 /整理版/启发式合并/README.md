# 启发式合并

**类型：** 混合型

**适用场景：** 每次枚举小容器合入大容器；保留颜色桶句柄交换与map统计两个原资料模型。

**复杂度与条件：** 位置桶总O(n log n+q)，map树上合并O(n log²n)；空间O(n+颜色数)。

[完整C++17板子](模板.cpp)。

## 核心接口

- `build(col,kinds)`：建立颜色位置桶，颜色先离散化为1..kinds
- `change(x,y)`：把逻辑颜色x全部变y，交换物理桶保证小并大
- `info/insert/merge`：map颜色频率统计：合并后mx及sum为众数频率与颜色和

## 例题 1：P3201 梦幻布丁

[原题](https://www.luogu.com.cn/problem/P3201)

**题意：** 把一种颜色的全部位置改色，并查询颜色段数。

**观察与规模：** 把一种颜色的全部位置改色，并查询颜色段数。 改色等价合并位置集合，段数只在搬运位置两侧变化。 每次整色重命名或合并孩子的统计容器，搬运代价与容器大小相关。

**朴素思路：** 始终把x枚举到y可能反复搬同一大集合；每点重新统计整棵子树O(n^2)。

**关键突破：** 物理上小容器并入大容器，每个被搬元素所在集合至少翻倍，因此最多搬O(log n)次。

**状态与建模：** P3201逻辑颜色id指向物理桶，a\[pos\]存物理桶号；CF600E每点容器存颜色频次及最高频率对应编号和。

**本题映射：** 把一种颜色的全部位置改色，并查询颜色段数。 改色等价合并位置集合，段数只在搬运位置两侧变化。 离线读取操作以压缩所有颜色；build、change，查询segments。

**转移与正确性：** 重命名x到y必须保留逻辑语义：先必要时交换id\[x\],id\[y\]，再搬物理小桶并重算每个搬运点相邻边的段数。树上先合并孩子map，再记录当前根sum。

**初始化与顺序：** build先建立位置桶和原段数；map加入当前点后递归合并孩子。释放小桶或清map，所有答案先记录再由父亲破坏合并。

**优化与限制：** 位置桶总搬运O(nlog n)，map每次操作还需log因子，为O(nlog^2 n)。交换桶句柄不等于交换x->y操作方向；否则外部颜色指令失真。

**本题复杂度：** O((n+q)log(n+q)+n log n)时间，O(n+q)空间。

**启发式总结：** 证明小并大要追踪具体元素所处集合如何翻倍；带有外部名字时把逻辑名字与存储位置分离。

## 共同思路与易错点

- 交换的是逻辑颜色句柄，不能简单颠倒x->y语义。
- map单次操作还有log因子；复杂度不能仅写O(n log n)。
- 数组边界使用显式判断，不依赖颜色0哨兵。

共同启发：证明小并大要追踪具体元素所处集合如何翻倍；带有外部名字时把逻辑名字与存储位置分离。
